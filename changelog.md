## [2026-07-28]

### Changed

#### Academy — one client, one request

The scenario ladder is gone. Academy is now a client list: **every client has
exactly one request**, the intern replies as their concierge in a WhatsApp-style
thread, and a separate evaluator scores the transcript on close.

**The two-panel surface (`/academy`)**

- `AcademyClientShell` — `ClientList` on the left (one row per client, their
  request as the preview line), `ClientConversation` on the right. Selecting a
  row opens the chat inline: no View button, no card to expand, no navigation.
- Threads are fetched on selection, not shipped up front — 176 conversations is
  far too much payload for content opened one at a time.
- Opens on the first client with unfinished business (`in_progress`, else
  `not_started`), rather than the top of an alphabet.
- The view is pinned to `h-[calc(100dvh-1.5rem)]`, so the page itself never
  scrolls — only the message list inside the panel does.
- Tabs: **Clients** / **Free practice** / **Cohort**. Cohort is trainer-only and
  gated server-side — a non-trainer hitting `?view=cohort` is silently returned to
  Clients before any data is fetched.
- `/academy/session/[id]` still opens a single session directly. A closed,
  scored session now **keeps the conversation on screen** and folds the report in
  beneath it (`ReviewToggle`) rather than replacing it.

**Sessions are created lazily**

Opening a client no longer creates a session — browsing 176 clients would have
written 176 junk rows. `getAcademyClientThread` renders the opening message from
the seed as a preview bubble; `startAcademySession` runs on the intern's first
reply and **returns the rendered opening message with the id**, so the previewed
bubble and the persisted transcript are the same line.

### Added

#### Academy — the 176-task curriculum (migrations 129–130)

Built from the real Indulge Retail Training register: **176 requests over 17
training days, 4–27 July 2026**, 2,079 messages reviewed. Source of truth is
committed at `supabase/seed-data/academy-task-register.json`.

- `129_academy_curriculum_structure.sql` — extends the difficulty CHECK to
  `easy | medium | hard | advanced | expert` (`hard` retained so the 24
  hand-written scenarios stay valid), adds the curriculum columns
  (`group_number`, `day_number`, `task_number`, `task_date`, `raised_by`,
  `brief`), a unique partial index on `task_number`, and the
  `academy_group_progress()` `SECURITY DEFINER` RPC — so an intern can read their
  own progress without being granted SELECT on `scenario_seeds`, which holds the
  answers.
- `130_academy_curriculum_tasks.sql` — the 176 tasks themselves, re-run safe via
  `WHERE NOT EXISTS` on `task_number`. Content is synthetic-safe: the register was
  scrubbed before authoring and the generator refuses to emit SQL if an email,
  phone number or long digit-run appears in any field.
- Columns, not a new table: a curriculum position is not an entity with its own
  lifecycle, so every existing RLS policy, server action and API route was left
  untouched.
- `lib/academy/curriculum.ts` supplies the tier map and `memberForTask` — 22
  given names × 8 surnames = 176 unique client names, generated by index so the
  roster can never drift out of step with the curriculum. **Every name is
  fictional and hard-coded on purpose**; putting a real member's name on a
  practice drill would leak PII onto a screen interns share.

#### Academy — performance-weighted progress

`lib/academy/progressScore.ts` replaces completion counting. Ten metrics with
fixed weights:

| Metric | Weight | Measured from |
|---|---|---|
| Task completion | 20% | telemetry — intern turns sent |
| Response quality | 20% | rubric — `brand_tone`, `closure` |
| Accuracy & completeness | 15% | rubric — `factual_accuracy`, `comprehension` |
| Time efficiency | 15% | telemetry — duration vs difficulty baseline |
| Overall AI assessment | 10% | rubric — `overall` |
| First-attempt success | 5% | telemetry — session count per seed |
| Critical thinking | 5% | rubric — `comprehension`, `escalation_judgment` |
| Communication | 5% | rubric — `brand_tone` |
| Research quality | 3% | rubric — `proactivity` |
| Consistency | 2% | history — vs the intern's running mean |

- `academyBar = Σ requestScores ÷ totalRequests`, so an unattempted request
  contributes exactly zero and the bar only reaches 100 by handling **every**
  request well. `qualityPercent` is reported separately as `Σ ÷ completed` — the
  honest answer to "how good am I", apart from "how far through am I".
- **Speed cannot buy a score.** Time efficiency is multiplied by response
  quality (`raw × max(0.35, quality)`), so a two-minute close on a poor answer
  cannot outrank a careful ten-minute one. Baselines: easy 8 min, medium 12,
  hard/advanced 16, expert 20; full marks at or under baseline, decaying to zero
  at triple.
- **Provenance is declared, not implied.** The evaluator emits six rubric
  dimensions, so four metrics are measured from session telemetry/history and six
  are proxied off rubric dimensions — every mapping is spelled out in
  `METRIC_SOURCE`. Extending the evaluator to emit all ten natively would change
  only `scoreRequest`.
- Weights are asserted to sum to exactly 1 by test, so a future edit cannot
  silently skew the bar. Surfaced by `ProgressRing`, `ProgressBreakdown` and
  `AcademyProgressHeader`.

#### Academy — real-time chat layer

- **Staged arrival** — only turns that have "arrived" render (`visibleTurns`).
  An undelivered client turn shows the typing indicator for a length-scaled beat
  (`typingDelayFor`: 420 ms + 55 ms/word, clamped to 700–2,200 ms here) and then
  lands. One message at a time, so a burst arrives in sequence.
- **In-thread mentor cues** (`lib/academy/mentor.ts`) — seven cues (`opening`,
  `first_reply`, `no_questions`, `good_probe`, `running_long`, `cap_warning`,
  `ready_to_close`), most-urgent-first, at most one per delivered message and
  **each fires at most once per session**. Anchored to the turn they follow and
  shown 450 ms after it lands, so they read as a reaction.
  **Cues are never persisted** — `training_turns` is the transcript the evaluator
  grades, and coaching inside it would both pollute the score and teach the
  persona to expect a coach in the room. They live in component state and die
  with the mount.
- Pure module, no model call: a cue is instant and can never pad or ramble.
- framer-motion entry animations throughout (`AnimatePresence`), sticky header
  and composer, a single scroll region, and stick-to-bottom that releases once
  the intern scrolls more than 80 px up.

#### Academy — attachments (migration 127)

- `training_turns.attachments jsonb NOT NULL DEFAULT '[]'` —
  `{path, kind, mime, name, size}`. **Append-only is preserved**: adding a column
  is a schema change, not a row mutation, and attachments are supplied at INSERT.
- A **private** `academy-attachments` storage bucket (50 MB ceiling,
  `image/*` + `video/*`), reached through server actions and short-lived signed
  URLs. Path convention `academy/{session_id}/{uuid}-{filename}` lets object RLS
  reuse `can_access_academy_session()` directly; the `[2]` segment is guarded by a
  UUID-shape regex **before** the cast so a malformed path cannot raise inside the
  policy predicate. SELECT + INSERT policies only — a shared attachment is part
  of the transcript.
- Images are inlined into the persona call as base64 blocks so the client can
  actually see them; videos cannot be inlined and are described instead.
- Partial index on turns that carry media, since most do not.

#### Academy — seed library expansion (migration 128)

12 more scenarios, **24 total, four per vertical**. Several are written to invite
a photo or video share, so the attachment path gets exercised. All synthetic;
re-run safe via `WHERE NOT EXISTS` on title.

### Fixed

- **Persona scenario drift.** The opening turn maps to `assistant` and Anthropic
  requires the first message to be `user`, so the route strips it — leaving the
  persona blind to the scenario the intern could see on screen. Observed live: a
  "harbour restaurant tonight" seed drifted into "Friday dinner in London".
  `buildPersonaSystemPrompt` now takes `openingMessage` and echoes it into the
  system prompt with an explicit consistency clause.
- **50-group ladder components removed.** `AcademyShell`, `GroupList`,
  `GroupLearningPanel` and `TaskCard` were deleted — an earlier ladder design
  that the one-client-one-request model replaced. `components/academy/` is now 13
  components, with no dangling references.

### Known issues

- **Founders get no Academy link in the sidebar.** `/academy` and
  `/admin/academy-seeds` are listed in `FOUNDER_NAV_SECTIONS`, but
  `FOUNDER_SIDEBAR_PREFIXES` does not include them — and the founder filter
  (`Sidebar.tsx`, `!isFounder || hrefMatchesFounderNav(item.href)`) strips both
  items out before `founderNavModels` can place them. Route access itself is
  fine; only the nav entry is missing.
- **`AcademyDifficulty` has not caught up with migration 129.** The TypeScript
  union in `lib/types/database.ts` is still `"easy" | "medium" | "hard"`, so
  `DIFFICULTY_PILL[display.difficulty]` in `AcademyChat` resolves to `undefined`
  for an `advanced`/`expert` curriculum task and the pill renders unstyled
  (`ScenarioPicker` has a `??` fallback; `AcademyChat` does not). The seed
  editor's Zod schema is likewise capped at `hard`, so trainers cannot author at
  the new tiers.
- **Group scaffolding survives beneath the client model.** `curriculum.ts` still
  exports `ACADEMY_TOTAL_GROUPS`/`resolveLadder`/`taskRangeForGroup`,
  `lib/actions/academy.ts` still exports `getAcademyLadder`/`getAcademyGroup`,
  the page's internal view key is still `"ladder"`, and the Free-practice copy
  still reads "outside the 50-group ladder". None of it is reachable from the new
  surface.

### Tests

**166 passing across 7 offline suites** — `academy-rubric`, `academy-pii`,
`academy-randomize`, `academy-evaluator`, `academy-persona-guardrails`,
`academy-progress-score`, `academy-mentor`.

`__tests__/academy-live-signoff.test.ts` hits the real Anthropic API and is
`describe.skipIf`-gated on `ACADEMY_LIVE=1` — skipped by default, never in CI,
because it costs real tokens. It covers the two things the offline suites cannot:
the persona is a *behaviour* claim, not a prompt invariant. Recorded run
(2026-07-28):

| Check | Result |
|---|---|
| Persona across 10 adversarial turns | 0 breaches, no scenario drift |
| Evaluator on a bad transcript, 3 runs | 1.0/5 each time — spread 0.0 |
| Evaluator on a mid transcript, 3 runs | 3.7–3.8 — spread 0.1 |

Together: anti-inflation *and* genuine discrimination.

## [2026-07-27]

### Added

#### Academy — foundation (migrations 124–126)

The original build. The persona/evaluator split, the append-only transcript and
the access model below are all unchanged; the ladder-of-scenarios surface it
shipped with was replaced on 2026-07-28.

**Database**

- `124_academy_department_enum.sql` — adds the `academy` value to the
  `employee_department` enum. Ships as its own migration because PostgreSQL
  forbids using a newly added enum value inside the transaction that adds it, and
  migration 125 references `'academy'` in a function body. (Same pattern as
  `122_employee_department_watcher.sql`.)
- `125_academy_core.sql` — four tables, two `SECURITY DEFINER` helpers
  (`is_academy_trainer()`, `can_access_academy_session(uuid)`), RLS on every
  table, and `training_turns` added to the `supabase_realtime` publication.
  - `scenario_seeds` — trainer-authored drills. Holds the secrets: the
    `hidden_constraints` array, `escalation_trigger`, `ideal_outcome` and
    `rubric_weights`. Trainer-only SELECT/INSERT/UPDATE; no DELETE policy —
    retirement is `is_active = false`.
  - `training_sessions` — one intern run of one seed. Carries `session_vars`, a
    per-session randomisation + safe display snapshot, so the intern UI never
    reads `scenario_seeds`. Intern reads/writes only their own; trainers read all.
  - `training_turns` — **append-only** transcript. `SELECT` and `INSERT`
    policies only; there is deliberately no UPDATE or DELETE policy, so a
    transcript can never be edited after the fact. Unique `(session_id, seq)`
    keeps the log gap-free.
  - `training_reviews` — evaluator output, one row per session (`session_id`
    UNIQUE). Readable by the owning intern or a trainer; writable by
    `service_role` only — there is no client-side insert path to a score.
  - **Ordering is load-bearing**: `can_access_academy_session()` is `LANGUAGE
    sql`, so PostgreSQL validates its body at CREATE time and it must be defined
    *after* `training_sessions` exists, or creation fails with `42P01`.
- `126_academy_seed_library.sql` — 12 starter scenario seeds, two per vertical
  (Global, House, Shop, Legacy, Dubai, GMR). Data-only; every seed is synthetic.

Standalone apply files for the whole sequence live in `supabase/manual/` —
`academy_part1_enum` … `academy_part8_curriculum_tasks`, of which **part 4 is
the read-only verify query**, so seven apply files and one checker. An earlier
combined `academy_124_126.sql` is also kept there.

**Access model**

- New `academy` department (`DEPARTMENT_CONFIG`, `DEPARTMENT_ROUTE_ACCESS`,
  `lib/validations/user.ts`), plus `isAcademyTrainer(role, department)` in
  `lib/types/database.ts` mirroring the SQL helper.
- **Trainer** = `admin` / `founder` / `super_admin`, or anyone with
  `department = 'academy'`. Trainers see the cohort, author seeds, and can open
  any session read-only.
- **Intern** = any other authenticated user. Owns only their own sessions.

**Persona engine (the simulated client)**

- `POST /api/academy/chat` — `{ sessionId, message }` in; **`text/plain`
  streaming** deltas out (not SSE, not JSON — read with `res.body.getReader()`).
  Runs `claude-haiku-4-5-20251001`, parsing Anthropic's SSE server-side and
  re-emitting plain text so the intern sees tokens immediately. The client turn is
  persisted in an `after()` callback, off the response path.
- `max_tokens: 200` — deliberately low, so replies stay message-length rather
  than drifting into email-length paragraphs.
- The persona system prompt (`lib/academy/persona.ts`) is assembled server-side
  from the seed plus the session's randomisation snapshot. It carries the hidden
  constraints — so the client can reveal them when correctly probed — but **never
  the rubric**. Explicit clauses forbid grading, coaching, or admitting to being
  an AI.
- Degrades rather than breaks: a missing seed, missing `ANTHROPIC_API_KEY`, or an
  upstream failure returns a canned reply with `X-Academy-Degraded: 1`.
  `X-Academy-Turn-Cap: 1` marks the last allowed intern turn; the cap is
  `ACADEMY_TURN_CAP` (24 intern messages). `409` = session closed or cap reached.

**Evaluator (the scorer)**

- `lib/services/academyEvaluator.ts` runs once on session close against the whole
  transcript, on `claude-opus-4-8` with structured output
  (`output_config.format` + a JSON schema, `max_tokens: 2000`), retrying without
  the format constraint if the API rejects that shape. Idempotent on
  `session_id`; a truncated response (`stop_reason: "max_tokens"`) or a missing
  dimension is never persisted.
- Six rubric dimensions — comprehension, brand tone, factual accuracy,
  proactivity, escalation judgment, closure — each scored 1–5 with a
  justification. `factual_accuracy` is weighted **1.5**; invented details are the
  worst failure mode. The **overall is computed in code**
  (`computeOverall`, a weighted mean rounded to one decimal), never asked of the
  model.
- Every review row pins `model_version` (`ACADEMY_EVALUATOR_VERSION`), so a later
  shift in scores can be told apart from a model or rubric upgrade.

**The persona/evaluator split** is the load-bearing design decision: the persona
holds the answers so it can reveal them under correct probing, and knows nothing
about scoring. All judgment happens afterwards, in a different call, on a
different model.

**Anti-memorisation**

- `lib/academy/randomize.ts` gives every session a fresh client name and date
  hint (substituted into `{{name}}` / `{{date}}` in the opening message) and
  mutates exactly one hidden-constraint value — a weekday shifted, or a small
  number nudged. The persona **and** the evaluator both read the mutated value, so
  the right answer moves per session and stays internally consistent. The
  override is recorded in `training_sessions.session_vars`.

**Seed authoring**

- `/admin/academy-seeds` — trainer-only, including the hidden constraints and
  per-seed rubric weights. Saves are refused when `scanSeedForPII` flags an
  email, phone number, long numeric run, URL or handle — seeds must stay
  synthetic.

**House rule**

`components/academy/` is built entirely from design tokens — **zero hardcoded
hex**, verified by scan. The `chat-*` tokens in `app/globals.css` are a
deliberate WhatsApp palette (`#075e54` header, `#25d366` accent, `#d9fdd3`
outgoing bubble, `#ece5dd` canvas); `globals.css` is the one place hex is
allowed, which is what keeps the components token-only.
